Spring PetClinic — TIBCO + OTel Edition

Local launcher for the current distributed stack

Frontend requests now flow through the backend over TIBCO ActiveMatrix BusinessWorks / EMS (JMS), and observability is handled by a local Splunk OpenTelemetry Collector with ActiveMQ/JMS metrics enabled.

PetClinic UI

http://localhost:8080/

Thymeleaf frontend and requestor service. Browse owners, pets, visits, and vets through the distributed app.

Backend Health

http://localhost:8081/actuator/health

Spring Boot Actuator health for the persistence and TIBCO JMS replier service.

OTel Collector Health

http://localhost:13133/

Health endpoint for the local Splunk OpenTelemetry Collector that receives app telemetry and ActiveMQ metrics.

OTLP endpoints: localhost:4317 and localhost:4318

TIBCO EMS Broker

localhost:61616

JMS broker (ActiveMQ mimicking TIBCO EMS) used by the frontend/backend request-reply flow and the Collector's metrics receiver.

Container: petclinic-tibco
Metrics config: TIBCO_METRICS_SETUP.md

Quick Start

./run-all.sh starts TIBCO, backend, and frontend.

./run-collector.sh up starts the Splunk OTel Collector with otel-tibco-metrics.yaml.

./run-otel.sh launches the apps with the Splunk OTel Java agent attached.

Use ./stop-all.sh to stop the apps and ./run-collector.sh down to remove the collector container.
